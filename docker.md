# Docker

## Image
An image is a static, read-only blueprint (like a recipe or a building plan) that contains the application code and its dependencies. 

## Container
A container is the live, executable process that spins up when you actually "run" that image, giving it active memory, a network, and a temporary file system.

The easiest way to understand this distinction is through the following parallels:

1. The Blueprint and the House

The Image (Blueprint): It defines exactly how the application should be built. It is unchanging and can be shared, stored, or copied countless times.

The Container (The House): It is the actual, livable house built from that blueprint. You can have five separate houses (containers) built from the exact same blueprint (image) on the same street.

2. The Cake Recipe and the Baked Cake

The Image (Recipe): A static list of ingredients and instructions written on paper.

The Container (Baked Cake): The tangible, edible result. It’s what happens when you follow the instructions and bring the recipe to life.

3. The Class and the Object (Object-Oriented Programming)

The Image (Class): The code template defining properties and methods.

The Container (Instance/Object): The actual, working realization of that class in memory.
